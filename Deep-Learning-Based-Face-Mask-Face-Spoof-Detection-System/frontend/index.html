CAN A CAMERA TELL IF A FACE IS REAL?

A deep learning system combining face detection and image classification to distinguish genuine faces, spoofing attempts, and masked faces — built on MTCNN and a fine-tuned ResNet18, served through a FastAPI inference endpoint.

Output Space

Three classes, one decision

Every prediction resolves to exactly one of these three labels. The model does not attempt to identify who the person is — only which of these categories the face belongs to.

Real

Genuine live face

A face captured directly from a live subject in front of the camera — no intermediate surface, no reproduction.

Classification labelreal
Spoof

Presentation attack

A face presented through an intermediate medium — a printed photo, or a phone or laptop screen held up to the camera — rather than a live person.

Classification labelspoof
Masked

Face with a mask

A live face that is partially covered by a mask, distinct from both an unmasked real face and a spoof attempt.

Classification labelmasked

System Design

How the system sees

Every uploaded image passes through the same nine-stage pipeline, whether it's a training sample or a live request to /predict. Expand a stage for detail.

Face Localization

Why MTCNN?

Before the classifier ever sees an image, the system needs to know where the face is. MTCNN (Multi-task Cascaded Convolutional Networks) locates faces and facial landmarks in a single pass, and is fast enough to run per-request in an API.

The current implementation, faithfully:

  1. Runs MTCNN on the uploaded image
  2. If more than one face is detected, keeps the one with the largest bounding-box area
  3. Expands that box by a 20% margin for context
  4. Clips the box to the image bounds and crops it
  5. Falls back to a plain resize if no face is found, rather than failing silently

Classifier

Why ResNet18?

ResNet18 is pretrained on ImageNet, so it already encodes general-purpose visual features — edges, textures, shapes — before it ever sees a single face. That transfer-learning head start matters when the task-specific dataset is far smaller than ImageNet.

The classifier keeps the pretrained convolutional backbone and replaces only the final layer with a small custom head:

  • 512-unit linear layer with ReLU activation
  • Dropout (p = 0.5) for regularization
  • Final linear layer projecting to 3 output classes

Data Pipeline

Where the training data comes from

Three source datasets are consolidated into the three target classes, then split reproducibly.

Face Mask 12K→masked / real
CelebA-Spoof→real / spoof
Anti-Spoofing Dataset→real / spoof

Each class is then shuffled with a fixed random seed and split:

70% TRAIN
15% VAL
15% TEST

Evaluation

How good is the model?

Honestly: unknown until you train it. This repository ships the evaluation code, not invented numbers.

No verified evaluation results are bundled with this project — accuracy depends on the raw datasets you provide locally. Run `python evaluate.py` after training to generate a real classification report and confusion matrix in /results.

Context

Why spoof detection matters

Face-based authentication that only checks "does this face match?" can be defeated by a printed photo or a screen held up to the camera — a class of attack known as a presentation attack. Treating real/spoof/masked as an explicit classification problem gives a downstream system a way to distinguish a live person from a reproduction, rather than trusting every visual match equally.

Limitations

  • ①Accuracy depends entirely on the training data supplied — none is bundled with this repository.
  • ②Lighting, image quality, and camera angle all affect real-world results.
  • ③Unseen spoofing techniques may not be reliably detected — the model only knows what its training data showed it.
  • ④Multiple simultaneous faces in one image are not supported — only the largest detected face is used.
  • ⑤This is a research/portfolio implementation, not a certified production security system.
  • ⑥A confident prediction is not a liveness guarantee — it should not be the sole gate for a security-critical decision.

Endpoints

Two routes, one model

POST /predict — accepts an image file, runs detection + classification, returns the predicted class and per-class probabilities.

GET /health — reports whether the model is loaded, which device it's running on, and the resolved class order.

Example request
$ curl -X POST http://localhost:8000/predict \ -F "file=@image.jpg"
Example response shape
{ "prediction": "real", "confidence": 0.9123, "all_probabilities": { "masked": 0.0244, "real": 0.9123, "spoof": 0.0633 } }
